# Five-Dimension Storyboard v8.2

默认使用中文。把输入转换为导演可审查、剪辑可执行、目标平台可生成的五维度分镜；保留细粒度导演节拍，但不要把导演节拍机械等同为一次生成任务。

## Required Reading

开始任务前按需完整读取：

1. `references/v8-core-template.md`：平台中立的导演、表演、摄影、连续性、声音和物理基础。
2. 一个平台配置：`references/platform-profiles/SD20-001_v1.0.md` 或 `SD25-001_v1.0.md`。
3. 使用 SD25 进行剧本/镜头表生成、STANDARD/LONG/ULTRA 选择或 4–30 秒封装时，再读取 `references/platform-profiles/SD25-AUTO-HYBRID_v1.0.md`。
4. 用户启用导演模块时，再完整读取对应导演模块。

不要加载未命中的平台、导演模块或专项模式参考。

## Rule Priority

发生冲突时依次服从：

1. 用户明确要求、原始剧本和不可更改项。
2. 台词原文与剧情因果。
3. 当前有效的项目配置卡 `PC ID`。
4. 当前平台配置、`MODE POLICY` 与逐任务 MODE。
5. `T-PHY`、动作因果、比例和动态连续性。
6. 人物、场景、道具、伤势和空间连续性。
7. 已加载导演模块的唯一总导演裁决。
8. 表演可读性、B/G 复杂度和生成稳定性。
9. 摄影与美学选择。

平台配置决定 `T-GEN`、参考容量、时间戳与执行封装；核心模板不再给所有平台写统一 T-GEN 上限。`SD20-001` 仍执行 4–15 秒；`SD25-001` 的 4–15 秒主要用于 STANDARD/T-BEAT，LONG、ULTRA 和专项模式服从各自配置。

v6.2 及更早模板已废止。用户明确要求旧版四行格式时，只压缩 v8.2 已完成的信息，不恢复旧规则。

## Platform Routing

以下表达加载 `SD25-001`：Seedance/即梦 2.5、SD25、30 秒长视频、180 秒超长视频、时间戳、视频延长、白模、高级视频编辑。新项目只说“Seedance”而未说明版本时，预填 `SD25-001 / AUTO-HYBRID`。

以下表达加载 `SD20-001`：Seedance/即梦 2.0、SD20。继续已有项目时复用其已锁定平台，不静默迁移。

## Project Start Gate

已有信息先预填，只集中确认真正缺失且会改变结果的项目级选择：

1. 平台与模式策略：SD20；或 SD25 的 AUTO-HYBRID、STANDARD-ONLY、LONG-PREFER、ULTRA-EXPERIMENT、LOCKED；专项编辑任务直接记录具体 MODE。
2. 导演系统：关闭、加载已有模块或当前项目临时自定义。
3. 成片总时长：固定、范围或自动推断，以及允许偏差。
4. 画幅、尺寸与安全区。
5. BGM、字幕与后期策略。
6. 剧本、分镜、提示词、字幕语言，以及台词是否逐字保留。
7. 摄影、美术、色彩、动作、声音与参考素材，以及禁用方向。
8. 交付范围：完整五维度、导演审阅、纯净提示词、失败诊断或专项任务。

默认预填：

- `SD25-001 / AUTO-HYBRID`；Natural/Timestamp 按每个生成任务决定。
- 基础导演模式；总时长按内容自动推断。
- 无 BGM；模型不生成字幕或说明文字；台词逐字保留。
- 剧本使用完整模式，现成镜头表使用执行模式，失败描述使用诊断模式。

用户选择 `STANDARD-ONLY` 时，确认摘要必须说明不会使用 16–30 秒能力。确认后建立 `PC-001`；配置变化建立新 PC 版本，不静默覆盖。


## Director Module

未启用模块时使用核心模板基础导演模式，不擅自指定真实导演。加载模块时验证 ID、版本、适用题材、原创边界和输出合同；加载失败则说明原因并回退基础模式。

用户说“启用/加载/使用 001”“DIR-PR-001”或“工业巨物电影团队”时，加载 `references/director-modules/DIR-PR-001_v2.1.md`，预填 `DIR-PR-001 v2.1 / TEAM-PR-001 / CR-PR-001`。孤立数字 `001` 不触发。

真实导演和影片只留在内部规划层，最终提示词必须转译为原创、可见、可听的方法结果。

## Workflow

完整任务按以下顺序：

1. `P 项目启动`：建立 PC、平台与 MODE POLICY。
2. `M 模块加载`：可选导演模块，输出唯一 DDC。
3. `A 导演规划`：五维度、风格/视觉锁定、色彩、情绪、连续性和 `B-ID` 节拍。
4. `B 镜头执行`：17 类导演字段、表演、声音、状态增量和物理控制。
5. `G 生成封装`：把 B-ID 映射为逐任务 `G-ID`、MODE、T-GEN、时间控制、资产和回退。
6. `C 自然生成`：把每个 G-ID 写成可见、可听、可表演的连续电影语言。
7. `D 平台执行`：输出生成、延长、编辑、预演或转场任务。

只把 C、D 的纯净执行内容投喂模型。内部公式、部门讨论、真实导演/影片和无执行价值的 ID 不进入纯净提示词。

## B/G/E Time Model

- `T-EDIT` / `E-TC`：最终成片实际使用时长与区间。
- `T-PHY`：故事世界中的物理事件时长。
- `T-SCR`：观众看到的银幕呈现时长。
- `T-BEAT` / `B-ID`：可独立审查和回退的导演节拍，通常 4–15 秒，一个主动作或连续情绪动作。
- `T-GEN` / `G-ID`：平台一次实际生成或编辑任务；可覆盖一个或多个连续 B-ID，范围由平台和逐任务 MODE 决定。

规则：

- 每个 G-ID 的本地时间轴从 `0s` 到其 `T-GEN`。
- 一个 B-ID 一个主动作；一个 G-ID 一个序列目标。
- 主执行方案中每个 B-ID 恰好由一个 G-ID 覆盖；回退方案可重复引用但必须标记 fallback。
- T-GEN 不自动等于 T-EDIT；需要剪辑选择空间时记录入点/出点余量，零余量写明理由。
- 时长由台词、表演、情绪、物理动作和连续性收益决定，不平均分配。
- SD25 AUTO-HYBRID 的合并判定、反碎片化审计和模式骨架以对应参考为准。

## Timestamp Policy

Natural/Timestamp 按 G-ID 选择，不做全片一刀切。

- `Natural`：起点、发展、峰值、余波和尾帧；不密集逐秒控制。
- `Timestamp`：只为必须准时发生的台词落点、转身、接触、爆炸、转场或不可逆事件设锚点。
- 锚点密度服从平台配置；不为呼吸、微表情、头发、衣物、雨雾、烟尘和背景运动设秒点。

## Core Generation Invariants

- 逐字保留台词、角色名和不可更改剧情；长台词只在自然停顿处拆分。
- 关键台词后安排听者反应；高潮保留纯表演或近似定镜空间。
- 每个 B-ID 写表演意图、视线、呼吸、身体重心和 2–3 个可见微表情变化。
- 每个 G-ID 继承上一实际生成尾帧；服装、伤势、道具、位置、光线、破坏、疲劳和动态状态逐段累积。
- 动态任务继承动作相位、速度、方向、角速度、支撑、动力和剩余位移。
- 全片只建一份 GSL；场景变化另建 BSL。
- 每个 G-ID 有环境声层；BGM、字幕、语言和音色服从 PC 与平台模式。
- 不新增剧本或镜头表中不存在的剧情事件。

## Camera Carry-Through

导演表保留：时间码、景别、角度、焦段、机位、运镜、构图、速度、站位、视线、画面、台词、表演、微表情、音效、视觉钩子和镜头功能。

纯净提示词把有效摄影意图转成可见语言。STANDARD 至少完整描述一次摄影语法；LONG/ULTRA 中每个 B-ID 都要携带景别、角度、焦段或空间意图、机位、运镜、构图和速度，不得只在段首写一套通用参数。

## Giant Subject Trigger

实体超过 15 米、人与巨物同框、巨物与建筑/巨物同框，或用户要求压迫、敬畏、渺小、城市级破坏时：建立固定 GMS、场景 SSR，模型需要比例参考时建立 VSC；主动动作或接触建立 PHY。长模式可以减少断点，但不得压缩 T-PHY，也不得丢失接触反作用、恢复姿态和动态尾帧。

公式只留在规划层，纯净提示词只写可见的蓄力、延迟、变形、力量传播、双方反作用、滑移、坍塌延迟和恢复。

## Multimodal Routing

SD25 为每个实际调用素材登记 Asset ID、控制职责、保持固定、禁止影响和优先级。纯净任务只列本 G-ID 实际使用的素材，不复制完整项目资产表。

冲突顺序：上一实际尾帧与不可更改身份 > GMS/SSR/VSC > 当前人物/场景 > 动作/运镜 > 风格。

EXTEND、EDIT、CAMERA-EDIT、BGM-REMOVE、PREVIS 和 TRANSITION 使用 SD25 专项规则，不套普通生成骨架。

## Delivery

完整导演审阅版依次提供：

1. PC、平台、MODE POLICY 和可选导演模块。
2. 五维度分析、主创决策、风格/场景/连续性锁定。
3. 触发时的 GMS/SSR/VSC 与物理规划。
4. `B-ID` 导演节拍表和详细镜头导演表。
5. `G-ID` 生成封装表：B 覆盖、MODE、T-EDIT、T-GEN、余量、序列目标、合并理由、时间控制和回退。
6. 多模态资产路由、跨段衔接与风险。
7. 模型纯净复制版：逐 G-ID 的实际有效提示词。
8. 自查结果。

用户只要提示词或镜头表时可以缩减展示，但内部仍完成平台、B/G/E 覆盖、时间、连续性、摄影和生成风险检查。

## Batching And Validation

超过 90 秒或预计超过 15 个 G-ID 时分批；每批最多 8 个主生成任务。LONG/ULTRA 的内部 B-ID 不计作额外批次任务。

交付前：

1. 完成核心模板与平台配置自查。
2. SD25 生成任务完成 AUTO-HYBRID 的覆盖、候选合并和反碎片化审计。
3. 可使用 `scripts/audit_storyboard.py <markdown>` 做确定性检查；错误必须修复，警告必须解释或修复。
4. 只向用户报告简短通过状态和真实风险，不输出内部推理。
