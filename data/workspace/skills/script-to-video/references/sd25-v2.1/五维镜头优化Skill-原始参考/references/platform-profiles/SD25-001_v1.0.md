## 1. Mode Policy And Capability Registry

`MODE POLICY` 是项目级选择，`MODE` 是每个 `G-ID` 的实际平台任务模式。不要用一个项目级 STANDARD 把整部剧本锁成短任务。

新建剧本或镜头表项目默认 `AUTO-HYBRID`：逐 G-ID 选择 STANDARD 或 LONG；只有完整场景满足高门槛时才使用 ULTRA。用户可明确选择 STANDARD-ONLY、LONG-PREFER、ULTRA-EXPERIMENT 或沿用旧项目 LOCKED。

进行 STANDARD/LONG/ULTRA 混合封装时，必须额外读取 `SD25-AUTO-HYBRID_v1.0.md`。AUTO-HYBRID 不是平台按钮，不写进提交给 Seedance 的 MODE 字段。

| MODE | 用途 | 时长/输入策略 |
|---|---|---|
| `STANDARD` | 稳定短镜头、单一动作、短表演 | 推荐 4–15 秒 |
| `LONG` | 连续表演、一镜到底、完整动作链、长对话 | 16–30 秒 |
| `ULTRA` | 完整场景、段落或超长叙事 | 最长 180 秒；内部必须拆节拍 |
| `EXTEND` | 延长已有视频 | 单次延长最高约 30 秒；多次延长总片段最长约 60 秒 |
| `EDIT` | 局部消除、替换、保留其他内容 | 明确“只修改”与“保持不变” |
| `CAMERA-EDIT` | 修改机位、视角并补全空间 | 锁定人物、动作和场景身份 |
| `BGM-REMOVE` | 移除背景音乐、保留人声和必要原声 | 声音编辑任务 |
| `PREVIS` | 白模、多宫格分镜、站位与轨迹控制 | 输入白模或分镜参考 |
| `TRANSITION` | 连接两段视频并补全间隙 | 同时输入前后视频 |

若产品界面可选能力与本配置不一致，以当前界面为准，并在项目配置卡记录差异，不伪造不可用能力。

## 2. Five-Level Time System

- `T-EDIT`：成片实际使用时间。
- `T-PHY`：故事世界中的物理事件时间。
- `T-SCR`：观众看到的银幕呈现时间。
- `T-BEAT`：内部导演节拍；推荐 4–15 秒，每个节拍只承担一个主动作或连续情绪动作。
- `T-GEN`：模型一次实际生成或编辑任务的总时长；由当前 MODE 决定。

核心关系：

- `STANDARD` 通常一个 `T-BEAT` 对应一个 `T-GEN`。
- `LONG` 可以把 2–4 个连续 `T-BEAT` 封装为一个 16–30 秒 `T-GEN`，但只能服务一个段落目标。
- `ULTRA` 可以包含多个 `T-BEAT`，必须先输出宏观段落表和时间戳节拍表，禁止写成没有内部结构的长段落。
- 巨物动作仍按 `T-PHY` 的自然相位规划；长模式只减少生成断点，不得压缩真实蓄力、接触、反作用和恢复。
- 每个 Prompt 的本地时间轴从 `0s` 开始，到当前 `T-GEN` 结束。
- 使用 `B-ID` 标识导演节拍，使用 `G-ID` 标识实际生成任务，使用 `E-TC` 标识最终剪辑区间；不要复用同一 ID 表示三者。
- `T-GEN` 不自动等于 `T-EDIT`。需要后期选择空间时记录入点/出点余量；零余量写明理由。

## 3. Duration Selection

按每个 G-ID 选择能稳定表达内容的最短模式：

- 4–7 秒：短反应、物件、单一冲击素材。
- 7–15 秒：完整表演、互动、巨物建立、单一动作链。
- 16–30 秒：连续对话、一镜到底、不可中断的完整物理动作、需要维持空间连续性的段落。
- 31–180 秒：仅用于完整场景或长叙事，不用于把无关镜头机械拼在一起。

切换到 `LONG` 或 `ULTRA` 前检查：

1. 长时长是否真正减少身份、空间或动作连续性风险。
2. 整段是否只有一个序列目标。
3. 内部每个 `T-BEAT` 是否仍可读。
4. 时间戳数量是否受控。
5. 模型失败时是否能按 `T-BEAT` 回退为独立生成。

连续 2–4 个节拍同场、同连续时间、同主要主体、同序列目标，合计可形成 16–30 秒且没有硬边界时，必须进入 LONG 候选评估。若最终仍全部使用 STANDARD，在生成封装表填写具体不合并理由；不设置固定 LONG 比例，也不为压缩任务数强行合并。

## 4. Timestamp Control

提供两种逐任务时间控制；同一项目可混用：

### Natural Mode

- 用动作起点、发展、峰值、余波和尾帧描述自然过程。
- 适用于细腻表演、呼吸、微表情、风雨、衣物、烟尘和连续物理动作。
- 不写密集秒点。

### Timestamp Mode

- 用于必须准时发生的转身、台词落点、接触、爆炸、转场、身份揭示或不可逆事件。
- 每个时间锚点必须绑定一个可见动作、可听声音或明确转场。
- 15 秒以内最多 4 个锚点；16–30 秒最多 7 个锚点；超长模式原则上每个 `T-BEAT` 只设一个核心锚点。
- 优先使用整数秒或清楚时间范围，不用无必要的小数秒。
- 不给呼吸、头发、衣物、雨雾、烟尘和背景人群逐秒编舞。
- 同一时刻不要安排多个互相竞争的主事件。

时间戳表：

| 本地时间 | T-BEAT | 必须发生 | 摄影/声音同步 | 状态增量 |
|---|---|---|---|---|
| `0s` | B01 | 开场状态 | 起始机位与环境声 | 无 |
| `{{Xs}}` | B02 | 核心事件 | 运镜、光线与声音触发 | 新变化 |
| `{{T-GEN}}s` | BN | 动态尾帧 | 保持未完成运动 | 供续接 |

## 5. Multimodal Asset Routing

官方手册当前说明的参考容量：

- 图片：单次最多 30 张。
- 视频：最多 10 个；单个约 2–30 秒；所有参考视频总时长不超过约 30 秒。
- 支持首帧、首尾帧、多模态参考和纯音频驱动。
- 支持音色参考、多人参考、白模和多宫格分镜参考。

实际界面限制变化时以当前界面为准。

每个输入素材必须登记：

| Asset ID | 类型 | 控制职责 | 必须保持 | 禁止影响 | 优先级 |
|---|---|---|---|---|---|
| `IMG-CHAR-01` | 人物图 | 面容、发型、服装 | 身份锚点 | 不控制运镜 | 高 |
| `IMG-SCENE-01` | 场景图 | 地标、色彩、空间 | 场景结构 | 不改人物身份 | 中 |
| `TAIL-01` | 上一尾帧 | 姿态、位置、动态 | 连续性 | 不重置动作 | 最高 |
| `VID-MOVE-01` | 视频 | 动作/运镜/节奏 | 可见运动规律 | 不复制角色/IP | 中 |
| `AUD-VOICE-01` | 音频 | 音色、语速、情绪 | 声线锚点 | 不改变台词原文 | 高 |
| `VSC-01` | 比例卡 | 巨物比例 | GMS/SSR关系 | 不控制剧情 | 高 |
| `GRID-01` | 多宫格 | 构图、景别、镜序 | 面板映射 | 不替代动态尾帧 | 中 |
| `PREVIS-01` | 白模 | 机位、站位、轨迹 | 空间调度 | 不决定最终材质 | 高 |

冲突时按：上一实际尾帧与不可更改身份 > GMS/SSR/VSC > 当前人物/场景参考 > 动作/运镜参考 > 风格参考。

项目资产总表用于审阅；每个纯净 G-ID 只列本任务实际调用的素材。不要把完整资产表复制到所有提示词。

## 6. Mode-Specific Rules

### GENERATE / STANDARD / LONG / ULTRA

- 一个 `T-BEAT` 一个主动作；一个 `T-GEN` 一个序列目标。
- 先建立 B-ID 导演节拍表，再建立 G-ID 生成封装表；主执行方案中每个 B-ID 恰好覆盖一次。
- `LONG` 和 `ULTRA` 必须先写节拍表，再写自然连续提示词。
- 摄影信息必须逐节拍携带，不能只在长提示词开头写一次通用机位。
- 台词按真实语速分配到节拍，保留停顿与听者反应。
- LONG 必须含 2–4 个连续 B-ID、16–30 秒、单一序列目标、剪辑余量说明和按 B-ID 拆分的失败回退。
- 需要明确后期硬切、换场、跳时、主视角/身份重置或参考体系重置时结束当前 G-ID，不跨硬边界合并。

### EXTEND

- 输入原视频或其实际尾帧，明确承接位置、姿态、速度、方向、角速度、支撑、动力、光线和声音余韵。
- 只写新增动作与状态增量，不复述或重演原视频已完成事件。
- 固定人物身份、服装、伤势、场景地标、镜头方向与画幅。
- 尾帧继续保持可延长的动态状态，除非剧情明确收束。

### EDIT / CAMERA-EDIT

- 先写 `保持不变`，再写 `只修改`，最后写修改后的自然物理反馈。
- 禁止因局部编辑改变人物身份、时长、台词、其他道具或未圈选区域。
- 修改机位时说明新方位、高度、角度、景别、焦段意图、构图和需要补全的空间。

### BGM-REMOVE

- 明确移除背景音乐，保留人物说话、环境声和剧情需要的拟音。
- 不改变画面、字幕和其他音频，除非用户同时要求。

### PREVIS

- 白模只控制机位、站位、运动轨迹、动作时机和空间比例，不锁死最终人物材质与美术。
- 多宫格分镜逐格映射 `T-BEAT`，补写每格景别、角度、焦段意图、机位、运镜、构图、动作和衔接。

### TRANSITION

- 分别锁定前视频尾帧与后视频首帧。
- 明确哪些人物、物件、运动方向、光线和声音必须连续。
- 只生成两段之间缺失的过渡，不重写两端内容。

## 7. Review And Feed-Ready Structures

导演审阅版先输出 `B-ID 导演节拍表` 与 `G-ID 生成封装表`。封装表至少包含：B-ID 覆盖、逐任务 MODE、T-EDIT 合计、T-GEN、剪辑余量、单一序列目标、判定码、合并/不合并理由、Natural/Timestamp 和回退任务。

模型纯净复制版按每个 G-ID 输出，只保留实际有效内容：

每个 Seedance 2.5 任务按需输出：

1. `【模型与任务模式｜SD25-001 / MODE / T-GEN】`
2. `【全局风格锁定】`
3. `【场景/节拍锁定】`
4. `【巨物比例锁定】`（触发时）
5. `【多模态资产路由】`
6. `【上一尾帧与本段连续性锁定】`
7. `【时间戳节拍】`（Timestamp Mode、LONG、ULTRA 时）
8. `【自然生成/延长/编辑提示词】`
9. `【台词与声音】`
10. `【负面限制】`
11. `【失败回退】`（LONG、ULTRA、编辑任务时）

自然生成提示词必须逐节拍携带景别、角度、焦段或可见空间意图、机位、运镜、构图和速度。

标题格式：

```text
Prompt XX｜SD25-001 {{MODE}}｜本地时间码 0s–{{T-GEN}}s｜{{Natural/Timestamp}}
```

纯净复制版不包含内部部门讨论、物理公式、未使用资产和只有管理作用的标签。公共 GSL 可以在审阅文档中只展示一次，但每个可复制任务必须能组合成完整独立输入。

## 8. Validation

- [ ] 当前 `PC ID` 已锁定 `SD25-001` 和 MODE POLICY；每个 G-ID 已选择实际 MODE。
- [ ] `T-BEAT` 与 `T-GEN` 已区分。
- [ ] B-ID、G-ID、E-TC 未混用，主执行方案中每个 B-ID 恰好覆盖一次。
- [ ] STANDARD/LONG/ULTRA 时长与内容匹配。
- [ ] LONG/ULTRA 只有一个序列目标，内部节拍可读。
- [ ] 每个 LONG 含 2–4 个连续 B-ID、16–30 秒、余量说明和短任务回退。
- [ ] 满足 LONG 候选条件却保持 STANDARD 的连续节拍已有具体不合并理由。
- [ ] `T-GEN` 没有机械等于 `T-EDIT`；零剪辑余量已有理由。
- [ ] 时间戳数量符合密度限制。
- [ ] 每个参考素材已有唯一控制职责和禁止影响项。
- [ ] EXTEND 没有重演原视频，动态尾帧完整继承。
- [ ] EDIT 已明确保持不变与只修改范围。
- [ ] 白模/多宫格没有替代人物身份、材质或动态尾帧。
- [ ] 摄影参数已逐节拍进入最终提示词。
- [ ] 纯净任务只列实际使用资产，没有混入内部审议标签。
- [ ] 失败时可按 `T-BEAT` 回退为短单元。
