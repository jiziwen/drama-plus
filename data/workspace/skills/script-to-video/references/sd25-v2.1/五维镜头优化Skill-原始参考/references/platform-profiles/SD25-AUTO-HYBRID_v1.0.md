# SD25 AUTO-HYBRID Packaging v1.0

> 适用：`SD25-001` 的剧本转分镜、镜头表转提示词、STANDARD/LONG/ULTRA 混合生成。  
> 不适用：`SD20-001`、单纯 EDIT/BGM-REMOVE、用户明确要求逐条保持现有生成任务的项目。

## 1. Outcome

保留细粒度导演节拍，同时减少没有必要的生成断点：

- 一个 `B-ID` 表示一个可独立审查和回退的导演节拍。
- 一个 `G-ID` 表示一次实际提交 Seedance 的生成任务，可以包含一个或多个连续 `B-ID`。
- 一个 `E-TC` 表示该节拍在最终成片中的剪辑区间。
- 一个 `T-BEAT` 一个主动作；一个 `T-GEN` 一个序列目标。
- 不以 LONG 数量或任务压缩率为目标，只在连续性收益高于生成风险时合并。

## 2. Mode Policy

项目配置记录 `MODE POLICY`，实际 MODE 在每个 `G-ID` 上决定：

| MODE POLICY | 行为 |
|---|---|
| `AUTO-HYBRID` | 默认。逐任务选择 STANDARD、LONG；完整场景满足高门槛时才选 ULTRA |
| `STANDARD-ONLY` | 所有任务保持 4–15 秒；确认时必须告知不会使用 16–30 秒能力 |
| `LONG-PREFER` | 满足安全门时优先 LONG；不跨硬边界，不牺牲回退能力 |
| `ULTRA-EXPERIMENT` | 仅在用户明确接受高重试风险时使用；必须同时保留短任务回退方案 |
| `LOCKED` | 沿用已有项目逐任务 MODE，不自动重封装 |

新建 SD25 剧本项目默认预填 `AUTO-HYBRID`。用户明确指定某一任务模式时服从用户；不要把单个任务的 MODE 误当成全项目只能使用该模式。

## 3. B/G/E Data Contract

### Director Beat Table

| B-ID | E-TC | T-BEAT | 场景/连续时间 | 主要主体 | 主动作 | 序列目标 | 摄影语法 | 硬边界 | 必需尾帧 |
|---|---|---:|---|---|---|---|---|---|---|
| B01 | 00:00–00:08 | 8s | 场景A/连续 | 角色A | 完成一个动作 | 目标X | 景别、角度、焦段意图、机位、运镜、构图、速度 | 无 | 状态增量 |

`硬边界` 只填写可观察事实：换场、跳时、闪回、平行线切换、身份/主视角重置、必须后期硬切或参考体系重置。情绪变化和普通运镜变化本身不是硬边界。

### Generation Packaging Table

| G-ID | B-ID覆盖 | MODE | T-EDIT合计 | T-GEN | 剪辑余量 | 单一序列目标 | 判定码 | 合并/不合并理由 | 时间控制 | 回退任务 |
|---|---|---|---:|---:|---|---|---|---|---|---|
| G01 | B01–B03 | LONG | 24s | 26s | 入/出点共2s | 目标X | MERGE | 同场连续动作链，合并降低空间断裂 | Timestamp | B01、B02、B03 STANDARD |

覆盖规则：

- 每个 `B-ID` 在主执行方案中恰好出现一次。
- 回退任务可以重复引用 `B-ID`，但必须明确标记 `fallback`，不计入主覆盖。
- 批次上限按 `G-ID` 计数，不按 `B-ID` 计数。
- `T-GEN` 是生成素材时长，不自动等于 `T-EDIT`。需要剪辑选择空间时记录入点/出点余量；余量为零时写明理由。

判定码使用有限集合，便于审计：`MERGE`、`HARD_BOUNDARY`、`MULTI_SUBJECT`、`ASSET_GAP`、`SYNC_RISK`、`USER_LOCK`、`NO_CONTINUITY_GAIN`、`DURATION_LIMIT`。LONG/ULTRA 使用 `MERGE`；保持 STANDARD 时选择最主要的非合并原因，并在理由列写可观察事实。

## 4. Packaging Decision Gate

按以下顺序决定，不先选模式再硬塞内容。

### 4.1 Hard Boundary Gate

命中任一项，不与边界另一侧合并：

- 换场、明确跳时、闪回或平行线切换。
- 主要身份、主视角、世界状态或参考体系重置。
- 剧情需要明确的后期硬切、黑场或不可跨越的省略。
- 合并后无法写成一个序列目标。

### 4.2 LONG Eligibility Gate

优先评估相邻的 2–4 个 `B-ID`。同时满足下列条件才是 LONG 候选：

- 同一场景和连续故事时间。
- 主要主体、空间轴线和关键道具关系可稳定继承。
- 合计可封装为 16–30 秒 `T-GEN`。
- 每个节拍仍有一个清楚主动作，整段只有一个序列目标。
- 合并能降低人物身份、空间、表演、动作相位或物理连续性风险。
- 参考素材足以锁定人物、场景和起始动态；失败后可按 B-ID 回退。

以下情况降低为 STANDARD 或缩短候选包：

- 同时竞争的主动主体过多，或多个高难不可逆事件需要模型同时精确完成。
- 摄影、空间或动作参考不足，长任务会放大漂移。
- LONG 必须依赖密集逐秒编舞才能成立。
- 核心台词、口型、复杂音画同步无法在当前资产条件下可靠完成。

### 4.3 ULTRA Gate

只有完整场景具有一个宏观目标、稳定参考/预演、可读的宏观段落表，并且用户接受更高重试成本时才使用。ULTRA 不是把若干无关镜头拼在一起的省任务工具。

### 4.4 Shortest Stable Choice

通过候选门后，选择能稳定表达内容的最短模式。STANDARD 是合理选择，但不是 SD25 剧本项目的全局默认结论。

## 5. Anti-Fragmentation Audit

完成封装后检查所有相邻节拍：

- 若连续 2–4 个 B-ID 同场、同连续时间、同主要主体、同序列目标，合计可形成 16–30 秒，且无硬边界，却仍全部使用 STANDARD，必须在封装表填写具体不合并理由。
- 不以“更稳定”“方便剪辑”作为充分理由；必须指出主体竞争、资产不足、必要硬切、同步风险或其他具体风险。
- 不设置固定 LONG 比例。题材、素材条件和用户风险偏好不同，不得为了通过审计强行拉长。

## 6. Per-Task Time Control

时间控制按 `G-ID` 选择，不做全项目一刀切：

- `Natural`：连续表演、呼吸、情绪发展、单一物理动作；用起点、发展、峰值、余波和尾帧描述。
- `Timestamp`：两个以上必须准时落点的不可逆事件、台词/动作同步、接触、爆炸、转场或身份揭示。
- STANDARD 最多 4 个必要锚点；LONG 最多 7 个；自然运动不设秒点。

## 7. Mode-Specific Prompt Contracts

### STANDARD

一个 B-ID 为主，写清开场状态、完整摄影机描述、一个主动作、情绪峰值、声音和动态尾帧。短于 4 秒的剪辑使用镜头仍生成平台允许的完整素材，并标出建议截取区间。

### LONG

必须依次提供：

1. 一个序列目标。
2. 2–4 个 B-ID 的本地时间戳节拍表。
3. 每个节拍自己的摄影语法、动作、表演、声音和状态增量。
4. 把节拍连接成连续电影语言的主体提示词。
5. 动态尾帧与按 B-ID 拆回 STANDARD 的失败回退。

LONG 可以有有动机的景别、机位和运镜变化，但不得变成无关蒙太奇。需要明确后期硬切时，在该处结束 G-ID。

### ULTRA

先写宏观段落表，再写各段 B-ID、局部时间锚点、资产/连续性接力和分段回退。没有预演或稳定参考时优先改为多个 LONG/STANDARD。

## 8. Review And Clean Deliveries

默认提供两层输出：

- `导演审阅版`：包含 PC、B/G/E 表、模式理由、内部 ID、资产职责、风险和回退。
- `模型纯净复制版`：每个 G-ID 只保留当前实际有效的风格/场景/连续性、资产、时间戳、主体提示词、台词声音、专项负面限制和回退提示。

项目级公共前缀可以在文档中只展示一次，但纯净复制版的每个独立任务必须能被完整组合。不要把未使用资产、内部审议过程或物理公式投喂模型。

## 9. Acceptance Checks

- [ ] MODE POLICY 已记录；每个 G-ID 有独立 MODE。
- [ ] B-ID 与 G-ID 未混用，所有主节拍恰好覆盖一次。
- [ ] 每个 LONG 含 2–4 个连续 B-ID、16–30 秒、一个序列目标和回退任务。
- [ ] 满足 LONG 候选条件却保持 STANDARD 的连续节拍已有具体理由。
- [ ] T-EDIT 与 T-GEN 未自动绑定；剪辑余量或零余量理由可见。
- [ ] Natural/Timestamp 按 G-ID 选择，锚点密度合规。
- [ ] 批次上限按 G-ID 计数。
- [ ] 审阅版与模型纯净复制版职责分离。
