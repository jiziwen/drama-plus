## 输入、确认与版本

- 一个项目包含多集。导入批次有正文场次号时，按集号归集，例如 `6-01` 与 `6-02` 同属第6集；同场跨 TXT 的续文按原文件自然顺序接续，保留来源章节和全部原文。没有前场可承接的无标文件保留并提示核对；整批没有场次号时，才沿用文件名或独立集标题识别分集的方式。
- 资产图在项目各集间共用，剧本、分镜卡、提示词版本、模型选择和生成任务按集隔离。处理和调整时明确当前集与卡片，不将别集内容写入当前集。
- 本流程的剧本在第一步确认；后续用只读原文核对。需要调整的是分镜编排与视频提示词，不借此重写已确定的剧情、人物关系、关键台词、能力、伤亡或胜负。
- 首轮仍只生成分段大纲。大纲包含每段目标时长、事件链、主体、场景、关键台词和段尾衔接；用户确认后才生成正式五列分镜。页面的确认操作对应原包聊天中的“可以／确认”。
- 原包“新任务建立新文件、保留历史”的要求在项目中对应每集独立记录、卡片和提示词版本；采用新候选后保留旧版，可恢复，导出新文件不覆盖以前交付。AI 调整先给候选并等待采用，失败或未采用不得覆盖当前正式版。

## 本项目时长与视频模型

- 先把整集主干剧情排进120秒以内，通常为四段。短剧本在最后的台词或动作完成时收束。除尾段外每段精确30秒，尾段大于0秒且不超过30秒。原稿标注的场次预计时长仅供查阅。
- 保留人物目标、决定和转折所必需的原因、动作及结果。跳过无效走位、等候和重复反应。把能同时发生的动作、表情与界面放在对白和心声进行时呈现，只给必须单独看清的动作或信息留出时间。
- 按说话人、原字和原顺序排完整集对白、心声和画外音，留出换气及换人应答的时间。单段拥挤时先使用相邻段落的余量，在自然停顿处接下一段，继承末镜的动作与声音。整集精简画面后人声仍说不完时，自动按必要秒数延长，满30秒另起一段。在末段大纲的「时长说明」写明需加时的对白和原因。
- 确认大纲后沿用用户编排的主干事件、顺序与资产选择。生成正式分镜时发现台词超出原分段，就按上述顺序自动调整段界、尾段或段数，直接继续制作。逐镜时长之和须精确等于调整后的本段秒数。时长取舍已由用户委托，只有确需用户补充剧情事实或资产时才发起确认。
- 本适配仅覆盖本流程的成片卡时长，不将原包所有“30秒”全局替换。完整保留原始示例、历史说明、平台 STANDARD／LONG／ULTRA 模式及 T-EDIT／T-GEN 的不同含义。
- 根据当前实际选中的视频模型安排生成任务，时长、图片数量、声音与输入形式以接入方实际能力为准。当前每张成片卡提交为一个真实生成任务；若超过模型单次时长或配图上限，选择支持该片段的模型，或回到大纲按原包的动作和对白边界拆段并重新确认。未接入分任务剪辑合成时，不宣称已自动生成或拼接多个 G-ID。平台文档中的 SD25 或 ULTRA 能力不能当作任意模型都支持的能力。

## 资产索引与 @ 引用

- 导入素材文件夹或 ZIP，按背景、道具、角色、生物目录建立索引；遍历子目录。保留完整文件主名、造型后缀、原始相对路径和稳定资产 ID。忽略系统元数据和非图片文件，不把不同造型合并成同一张图。
- 编辑视频提示词时逐字采用资产清单显示名写 `@资产名`，显示名通常是去扩展名的完整文件主名；同名消歧后的路径或编号也是显示名的一部分。名称含空格、标点、下划线时仍按完整名称匹配，优先识别最长完整名称。
- 所有角色的造型由模型结合已确认剧本、本集选图说明和已导入资产自动选择。优先使用用户确认的绑定和原文指定的造型。普通出场优先用真人常态图，沿用到原文明确换装或伤势变化的节点。原文明示的 Q 版小剧场用对应 Q 版图，与真人同镜时分别引用两张图。真人的内心 OS 沿用真人造型。大纲直接记录选择及资产 ID。
- 每张卡以资产 ID 绑定造型。承上、机位、画面、对白说话人、音效和衔接都能关联资产。可唯一定位的角色简称关联本段造型；多套造型共用简称时用完整显示名消歧。口播内的人名保持原词，引用信息放在台词之外。提交、复制与导出共用本段的素材编号、角色音色和最终文本。
- 提示词中的每个引用必须能找到图片且绑定到当前卡。删除、改名、替换素材后核对引用和历史候选；未补齐的素材不能静默忽略。
- 原包五列表格仍为 `镜号｜时长｜景别／机位／运动｜画面与动作｜对白／音效`。资产索引、B/G 封装和内部审核不添加成独立的打光、怪物、武器或资产列；镜头和模型提示词按原规则写可见画面、动作、声音及连续性。

## 正式稿的数据与展示

《04-正式输出模板.md》的全部结构在项目记录中保留：整集制作规格、人物与声音锁定、界面提示词（如有）、逐段的真实承上、场景、人物、精确总时长、独立生成说明、五列表格、末帧衔接，以及逻辑与节奏复核。summary 只是大纲摘要，不能代替上述正文。第一段没有前场资料时如实说明；末段按实际收束，不编造下一场。

生成正式分镜时，按本次请求指定的片段范围提交 cards。整集制作规格、人物与声音设定只提交一次，后续片段沿用已收到的设定。本批首段从请求提供的上一段实际末镜接起，批内相邻片段依次承接站位、朝向、动作、持物、伤势和声音。遇到原文换场或跳时，写明过渡。按整集原文核对主干剧情、台词和说话人；大纲确定事件顺序与资产，段界依本项目时长规则自动调整。使用本集剧本与大纲涉及的资产和所需的完整 Skill 章节。

程序保存已收到并通过局部检查的完整片段。生成中断后，用户可以从已保存的末镜续写。所有片段完成后，程序按整集原文、实际分段和资产索引做 TypeScript 校验。整集通过后再采用正式分镜并从逐镜正文渲染视频提示词。需要额外检查空间、动作与剧情承接时，用户可主动进行整集 AI 复核。

对白／音效栏保留人物、具体情绪、语速和必要的音量、心声／画外标记及自然音效；原台词逐字保留。心声由本人原音念出，表情、口型与动作依原规则处理，不因结构化存储剥去表演信息。

视频提示词从同一份正式分镜、人物声音锁定、逐镜景别机位、动作、对白和音效逐项渲染，并按绑定资产加入 @引用，不再另写一份压缩摘要。手动修改镜头后保留旧提示词为草稿，待同步后才能交付或提交视频。生成、采用、重新载入、单段／整集导出都保留同一完整结构；旧稿缺字段时明确提示重新生成，不用固定套话补齐。

## TypeScript 自动检验

参照 [校验执行说明](references/validation.md)。原包三个 Python 文件完整保留在 `references/sd25-v2.1/` 中作为来源和回归参考，本项目运行时不调用 Python，不执行原文中的 Windows PowerShell 示例。运行入口统一为本 Skill 的 TypeScript 脚本，网页使用同一纯 TypeScript 核心。

每次生成或修改正式分镜、提示词候选后自动检验；校验问题集中修正相关片段或镜头。分批生成时每批有三次 AI 自动修复机会，整集单次生成时整集共用三次，每次修改后重新执行本地校验。用尽后显示仍未通过的具体问题，保留已确认稿与已保存的草稿。只有剧情事实或缺图确需用户决定时提示具体项；程序错误保留内部诊断。手工编辑允许保留未完成草稿，采用、生成视频与导出前重新自动检查。用户无需点击独立检验按钮。

新大纲生成与确认时，程序额外核对非尾段精确30秒、尾段大于0秒且不超过30秒；不合格时重新编排剧情边界，不直接拉伸旧镜头或改时长数字。既有正式稿的时码随版本保留，重新生成时按本次实际分段校验。逐镜时长、30秒上限、完整封装与资产引用继续由程序核对；原文台词、因果、人物身份、空间轴线、动作受力、界面可读、镜头节奏、伤势道具和承上／衔接仍须依完整自检表逐项检查。结构检查不能代替这些写作检查。通过后才采用或交付，正式分镜与提示词不出现内部 PASS／FAIL、算式或审计痕迹。
