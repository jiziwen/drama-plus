# 剧本转视频的分集存储与协作

编辑采用字段级后写生效。分集、片段和镜头通过稳定 ID 寻址，未修改的内容不会随旧页面一起提交。在线提示不授予或撤销编辑权限，网络中断不会关闭分集。

## 读取与保存

接口前缀为 `/api/v1/script-video`。

| 接口 | 返回内容 |
| --- | --- |
| `GET /projects?view=summary` | 项目 ID、标题、版本，不含分集正文 |
| `GET /projects/:id?view=summary` | 共享资产、设置及分集摘要，不含剧本、镜头表和历史成片正文 |
| `GET /projects/:id/episodes/:episodeId` | 当前分集正文、项目版本和分集版本 |
| `PATCH /projects/:id/changes` | 只保存实际改动，返回共享摘要、触及/请求的分集正文及确认序号 |
| `GET /projects/:id/episodes/:episodeId/activity` | 轻量任务、分集版本、排队及生成中的片段 ID |

旧的全项目 GET/PUT 保留兼容用途。新版编辑器不使用整项目 PUT；旧 PUT 仍检查项目版本，避免旧页面覆盖新系统的数据。

改动协议见 `backend/src/services/script-video-sync.ts`。`project`、`asset`、`episode`、`card`、`shot` 分别限定保存范围。普通字段按最后被服务器接受的写入生效；嵌套设置按字段更新，镜头按自身 ID 和字段更新。增加、删除与排序单独表示。任务、成片地址、分镜版本和生成状态由服务端维护，不能夹带进草稿覆盖。

每个页面的写入者使用独立 `clientId`，递增 `sequence`，严格串行发送。超时重试复用原序号，服务端幂等确认，不把同一次重试当成新编辑。同一 `clientId` 不支持并行发送不同增量。离线旧稿在重连后提交时可以覆盖他人随后保存的同一字段，这是后写生效的预期行为。

普通改动只读写相关分集。资产名称/删除和统一风格等确实影响全项目的操作才遍历其他集。服务端依据最新资产表校验新增引用，避免旧页面重新绑定已删除的资产。

## 本机草稿

IndexedDB `script-video-local-edits` 的 `project-drafts` 保存尚未确认的改动、基线、页面身份和发送中的批次。草稿按站点账号、标签页、项目隔离，同一标签页刷新可以恢复，复制标签页使用独立身份。

界面区分“已保存到本机，等待同步”和“项目已同步”。本机写入失败时不宣称草稿已保存；浏览器存储被清理后无法恢复本机草稿。重新连接同步编辑内容，不自动补发付费生成请求。账号变更时原账号草稿暂停同步。

## 生成任务与素材

进入任一分集都不会独占其他分集或共享资产。多人在线提示使用页面会话区分同一账号的多个标签页。

批量生成先登记待提交片段，排队预约两分钟过期，由发起页面每三十秒续报。报价等待期间也保持预约。实际提交后由持久化生成任务接管占位，按片段 ID 原子防重，不因编辑导致版本改变而解除。其他页面即使原来没有任务，也会周期查询状态，恢复到前台时立即查询。预约过期后不会自动发起生成。

取消一个批次按该页面的请求标识匹配，显式取消任务按任务 ID 匹配。排队/进行中的删除保护与编辑权限分开；一般文本、图片编辑仍可继续。

资产库只保存当前资产内容，同 ID 换图会让后续提交使用新文件。已经完成的视频不会重新渲染；使用旧输入完成的任务仍保留成片，输入发生变化时可作为历史成片查看。

只有本应用管理的 UUID 上传文件进入退休清理队列。旧文件先由准备中的任务临时持有，再交给持久化的 `sys_task.params`。其他项目、常规素材库或未完成的任务仍引用时继续保留。任务后台终态会触发清理，无需打开编辑页面；提交/取消结果未明时继续保留，确认后再清理。清理记录与准备阶段持有可在重启后恢复，原图和缩略图一起处理。

## 存储迁移与回退

数据仍位于原数据卷的 `script-video/projects/`。`workspace.sqlite3` 分表存放共享项目、分集正文与任务；`video-queue.sqlite3` 存放等待提交的预约。WAL 文件属于数据库工作文件，备份运行中的数据库应使用 SQLite 备份方式或停机后复制完整数据目录。

首次启动事务导入旧 `<project-id>.json`，记录已导入标志并原样保留源文件。新编辑只写 SQLite，不双写旧 JSON。旧 JSON 因而是迁移时快照，直接回退旧程序不会包含迁移后的编辑；需要带回最新内容时，应先从新数据库导出旧格式。原文件保留不等于素材历史备份，已退休素材会按上述规则清理。

## 本地验证

相关测试命令：

```sh
cd backend
node --import tsx --test tests/script-video-*.test.ts
npm run build
cd ../frontend
node --import ../backend/node_modules/tsx/dist/loader.mjs --test tests/script-video-*.test.ts tests/script-video-*.test.mjs
npm run generate
```

同时有 Nuxt dev 进程时，生产生成需要独立 buildDir，避免共享 `.nuxt` 产出开发入口。验证生产 HTML 应引用实际存在的 `/_nuxt/<hash>.js`，不能引用 `@vite/client`。

2026-11-21 本地隔离百集样本的未压缩整包 8,807,321 B，目录 137 B，共享摘要 17,209 B，单集正文 88,156 B。接口基准小于 1 ms，旧 JSON 冷迁移约 57 ms。浏览器隔离样本刷新时目录、摘要、当前集正文在导航开始后约 222 ms 收齐。该结果是 localhost 合成数据验证，线上两秒目标需要发布后以真实项目及网络再次测量。

浏览器另验证了真正离线时草稿落盘且服务器正文不变、重连自动同步、刷新恢复、同集多人进入和跨页面排队状态禁用生成按钮。计费生成使用隔离测试模拟供应商，没有为本次验收提交真实计费任务。
